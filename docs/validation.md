# 验证方法与边界

本版发布验收由随包 `validation-report.json` 记录，绑定源码提交及实际 DLL 哈希。源码仓库提供复现方法；不能把文档中的验收要求当作已经完成的结果。

每种架构必须通过全部 13 项 CTest，包含 ABI、输入与内核、真实加载、异常原子输出、完整审计生命周期、范围和续算状态，以及两个既有性能门禁。保留多短线段与窗口增长阈值，不进行新的速度优化。

整理前后对照使用 seed=20260828 的 5,000 组随机输入，以及已有合成定向、镜像、前缀与非法输入派生。对正式、实验恢复、OFF 三种策略比较事件及完整审计；实际加载两版 DLL，比较函数 1/2/99。正式语义范围另与 Python 参考进行事件和审计对拍。零差异证明本次整理保持相应样例上的行为，不证明所有输入都正确。

历史研究存在未完成的最终组合全量验收，算法三项 99% 目标也没有达到。这些状态作为首版限制保留，不用本次合成验证替代历史外部参考统计。恢复机制为工程策略，不自动解决待定的理论分歧。

公开工程、CTest 和合成发布检查不依赖 CZSC、授权服务器、私人行情或客户端配置。历史私人语料和报告留在本地研究归档，不属于公开验证集。

GitHub Actions 配置已提供，本次本地交付没有远程 CI 运行记录。真实客户端中的公式导入、渲染与交互人工验证未执行。Windows DLL 自加载和回调测试已经纳入工程验收，具体结果以发布报告为准。

源码包还应在含中文和空格的新目录中解压、独立构建并通过基础检查。该结果记录于随包验证报告，避免依赖原开发目录。
