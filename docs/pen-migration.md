# 笔计算迁移与宿主验收

`v0.1.0-rc.2` 将四份原公式中的笔计算移入 DLL。原表达式冻结在 [legacy_pen_formula.txt](../tests/fixtures/legacy_pen_formula.txt)，由独立的 [Python 解释器](../reference/pen_formula_reference.py)读取，用于自动对拍；它没有调用 C++ 结果来产生预期值。

## 三数组接口如何接收四项信息

原公式需要 H、L、C、DAY。C 只用于比较 MA(C,5) 与 MA(C,10)，DAY 只用于判断相邻 K 线的 DAY 是否不同。新增接口如下：

| 函数 | 输入 | 输出 |
|---|---|---|
| 10 | C、DAY、C | bit0 快均线较高，bit1 慢均线较高，bit2 DAY 改变，bit3 均线尚未有效，bit4固定格式标记 |
| 11 | H、L、函数10输出 | bit0 原 CLG3SAFE，bit1 原 CLD3SAFE，范围 0..3 |

第三输入复用C序列，并校验与第一输入一致，避免依赖宿主对常数参数的展开方式。两个接口均无跨调用状态。DAY 保持原公式的日号含义，取值1..31，不改用 DATE，也不推断日历。相邻日期恰为不同月份的同一日号时，原公式不视为 DAY 改变；本版保留这个行为。

函数10结果范围16..31，bit4恒为1，用于拒绝旧DLL缺少入口时返回的零。公式同时校验该标记，版本混用不能当作合法空结果。函数10的均线比较互斥，预热位与比较位互斥。函数11校验每个编码以及 H≥L；非有限数据、非法日号、不一致的收盘价副本、非法编码都按原子错误协议处理。C++ 输入类型分别为 `TdxPenContextView` 和 `TdxPenSeriesView`，不复用 `TdxSeriesView` 的字段含义。输出长度与原输入相同，内存归调用者所有。

公式把函数11的两个位分别还原为 CLG3/CLD3用于绘图，随后沿用顶优先的 `1/-1/0` 笔事件。错误值64沿流水线传递，不能悄悄变成合法空笔流。函数1、2、99及原 C++ 接口、事件位、错误码均不改变。

## 保留的表达式与边界约定

保持原分型窗口、BACKSET 回填、均线平手处理、包含关系、跳空计数和距离筛选。`CLD1` 最后分支原本使用 `REF(H,BARSLAST(CLD1X))`，本版照录，不将它改为 L。函数11同时保留顶底标记，即使同一根 K 线同时命中两者，也不会在绘图前丢掉一个。

自动参考明确采用以下约定：

| 运算 | 参考与 C++ 采用的约定 |
|---|---|
| MA | 满N根后有效；以double求和，结果转为binary32再比较 |
| REF | 引用超出左边界时无效，不自动补首值 |
| BARSLAST | 尚无条件成立时为已处理根数，即第0根为1；命中当根为0 |
| HHV / LLV | N=0从首个有效值开始；N大于已有长度时使用已有窗口；忽略无效值，全无效则无效 |
| COUNT | N≤0使用所有已处理值；无效条件不计数 |
| BACKSET | 覆盖当前及之前共N根，左边界截断；整个快照计算，可以回填 |
| 比较、AND、OR、IF | 无效操作数传播无效；IF条件无效则结果无效；ISVALID在末尾还原安全标记 |

[通达信官方函数表](https://help.tdx.com.cn/gspt/docs/markdown/redword/functionlist.html)说明了一般函数用途和N=0等规则，但没有完整定义上述全部起始窗口、无效值传播和均线浮点求和边界。这些约定不能仅凭文档或第三方解释器当作宿主已验证事实。

维护者目前没有当前笔公式的通达信导出数据，也没有可直接调用的宿主公式测试入口。因此自动对拍只验收“冻结公式参考语义与迁移实现一致”，通达信实际语义对照仍待执行。这项状态必须保留在发布报告中。

## 通达信内怎么验收

1. 绑定本版 DLL 与公式到同一槽位，打开 `05_笔计算迁移对照公式.txt`。它在同一窗口同时执行原笔公式和新 DLL。
2. 检查“顶差异、底差异、笔差异、上下文差异、加载错误”，以及三项线段/接线差异；全部应为0。
3. 分别检查不足10根、平价/同价极值、从未出现一类分型、同日与跨日跳空、月末跨月、前缀逐根增长、切换周期及改变历史范围。不能只在一张长图上看最终两条线。
4. 保存客户端版本、位数、历史范围和各差异数。任何非零都暂停“笔迁移完全验收”，先定位内置函数的差异；不要用修改线段规则来掩盖它。

## 自动验证

原13项 CTest保留，新增 `pen_formula_selftest` 与 `pen_formula_dll_crosscheck`。前者覆盖基础运算边界、月末、上下文校验和错误输出；后者通过真实注册回调检查上下文、顶底标记、镜像、前缀、端点变化和交错顺序。

发布扩展对拍使用固定种子20260828、5000组随机 OHLC 输入及派生。真实 DLL 新旧函数1/2/99使用相同的参考笔流比较结果；既有发布检查继续比较旧线段三策略事件与完整审计。详细次数和哈希以同提交验证报告为准。
